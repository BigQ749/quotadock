# 架构说明

## 总体结构

```text
同步器 / Chrome 扩展 / 用户脚本
              |
              v
     本地 JSON 额度快照
              |
              v
quota_fusion_host.ps1  ----  多卡片、拖拽、合体、藏边、托盘状态
              ^
              |
quota_center.ps1  --------  平台选择、显示状态、添加/删除自定义平台
```

`quota_center.ps1` 是控制面板；`quota_fusion_host.ps1` 是真正的浮窗宿主。启动器通过临时请求文件把“打开/关闭/移除”请求交给宿主，避免每个提供商生成一套原生窗口。

## 数据边界

- 视图层只读取本地 JSON；它不需要第三方 API Key。
- OpenCode Go 后台同步单独处理认证，并把结果写入 `%LOCALAPPDATA%\QuotaDock\data\opencode_go.json`。
- 凭据和运行状态放在 `%LOCALAPPDATA%\QuotaDock`，不放在仓库目录。
- Git 仓库只包含代码、公开示例、品牌来源说明和脱敏截图。

## 为什么没有把所有平台写死

不同平台的额度窗口不同，且公开 API 的稳定性不同。QuotaDock 把适配器输出压缩成统一 JSON，再由宿主统一绘制，因此新增 Claude Code 或其他平台时只需新增同步器/转换器，不用重写拖拽和 UI。

## 合体模型

合体不是把两个独立窗口“贴”在一起，而是宿主窗口内部的多个卡片。这样拖拽、最小化、藏边、关闭和状态同步都只有一个真实窗口，避免闪烁、漂移和托盘状态与实际窗口不一致。
